# คู่มือ LINE Shopping (MyShop) ภาษาไทย — มีตั้งแต่ v2.0

> สั่งงานร้าน LINE Shopping ของคุณด้วย "ภาษาคน" ผ่าน AI — เพิ่มสินค้า เช็กออเดอร์ ส่งของ ออกใบปะหน้า ดูเงินเข้า และสร้างลิงก์จ่ายเงินปิดการขายในแชท โดยไม่ต้องเปิดหน้าเว็บ MyShop เลย

คู่มือนี้สำหรับ **เจ้าของร้าน / แอดมินเพจ** ที่เปิด LINE Shopping ไว้แล้ว และอยากสั่งงานผ่าน AI host (Claude Cowork, Claude Code, Cursor ฯลฯ) อ่านจบแล้วจะตั้งค่าเองได้ และรู้ว่าเครื่องมือทั้ง 14 ตัวทำอะไรได้บ้าง พูดยังไงให้ AI ทำให้

ถ้ายังไม่เคยตั้งค่าตัว MCP เลย แนะนำอ่าน [`quickstart-th.md`](quickstart-th.md) ก่อน แล้วค่อยกลับมาเปิดส่วน Shopping ที่นี่

## 1. LINE Shopping (MyShop) คืออะไร

**LINE Shopping (MyShop)** คือระบบร้านค้าในตัวของ LINE Official Account — มีสินค้า ตะกร้า ออเดอร์ การจ่ายเงิน และการจัดส่งครบในตัว ลูกค้าซื้อของจบในแอป LINE ได้เลย

สิ่งสำคัญที่ต้องเข้าใจ: **MyShop เป็นคนละระบบ (คนละ API) กับงานส่งข้อความ (Messaging)** ของ LINE OA

| | งานส่งข้อความ (Messaging) | LINE Shopping (MyShop) |
|---|---|---|
| ใช้ทำอะไร | broadcast, rich menu, Flex, คูปอง, insight | สินค้า, สต็อก, ออเดอร์, เงิน, ลิงก์จ่ายเงิน |
| กุญแจที่ใช้ | Channel Access Token | **MyShop API Key** (คนละตัว) |
| ต้องเปิดใช้ก่อนไหม | มากับ OA อยู่แล้ว | ต้องเปิด LINE Shopping + ขอ API Key เอง |

เพราะเป็นคนละกุญแจ เครื่องมือฝั่ง Shopping ทั้ง 14 ตัวจึง **"โผล่ก็ต่อเมื่อใส่ MyShop API Key เท่านั้น"** — ถ้าคุณยังไม่ใส่ key จะเห็นแค่เครื่องมือฝั่งข้อความ 34 ตัวตามปกติ (นี่คือสิ่งที่ตั้งใจออกแบบไว้ ไม่ใช่บั๊ก)

> 💡 **ปิดการขายในแชทได้จริง** — จุดเด่นที่สุดของ v2.0 คือ `line_create_checkout_link` ลูกค้าทักมาคุย คุณสร้างลิงก์จ่ายเงินส่งให้ในแชท ลูกค้ากดจ่ายจบ ไม่ต้องให้ลูกค้าเดินไปหาสินค้าเองในร้าน

## 2. สิ่งที่ต้องมีก่อนเริ่ม

1. **LINE OA ที่เปิด LINE Shopping (MyShop) แล้ว** — เปิดใช้ฟรีที่ [oaplus.line.biz](https://oaplus.line.biz)
2. **สิทธิ์ Admin** ของ OA นั้น (ต้องเป็น Admin ถึงจะออก API Key ได้)
3. **ตัว MCP ตั้งค่าใช้งานได้แล้ว** — เห็นเครื่องมือฝั่งข้อความทำงานปกติ (ลองสั่ง "ดูสถานะ OA" ได้)
4. **(ถ้าจะลงรูปสินค้า)** ที่ฝากรูปแบบลิงก์ HTTPS ตรง — เพราะ MyShop ไม่มีปุ่มอัปโหลดรูป ดูหัวข้อ [กฎความปลอดภัย](#7-กฎความปลอดภัยที่ต้องรู้)

## 3. ตั้งค่า MyShop API Key (ทีละขั้น)

### ขั้นที่ 1 — ขอ API Key

1. เข้า [oaplus.line.biz](https://oaplus.line.biz) แล้วเลือก OA ของคุณ
2. ไปที่ **Settings (ตั้งค่า) → API keys**
3. กด **Generate** เพื่อสร้างกุญแจใหม่ (ต้องเป็น role **Admin**)
4. คัดลอกกุญแจเก็บไว้ — **ปฏิบัติกับมันเหมือนรหัสผ่าน** อย่าให้หลุด อย่าวางในโค้ดหรือแชทสาธารณะ

### ขั้นที่ 2 — ใส่กุญแจลง config

**แบบร้านเดียว (single-OA)** — เพิ่ม `LINE_MYSHOP_API_KEY` เข้าไปใน `env` block เดิม:

```json
{
  "mcpServers": {
    "line": {
      "command": "npx",
      "args": ["-y", "line-oa-mcp-ultimate"],
      "env": {
        "LINE_CHANNEL_ACCESS_TOKEN": "ใส่ channel token จริง",
        "LINE_MYSHOP_API_KEY": "ใส่ MyShop API key จริง"
      }
    }
  }
}
```

**แบบหลายร้าน (multi-OA)** — ใส่ `"myshop_api_key"` ต่อ OA ในไฟล์ `~/.line-mcp/config.json`:

```json
{
  "default_oa": "main",
  "oas": {
    "main": {
      "channel_access_token": "TOKEN_1",
      "display_name": "ร้านหลัก",
      "myshop_api_key": "MYSHOP_KEY_1"
    },
    "client_a": {
      "channel_access_token": "TOKEN_2",
      "display_name": "ร้านลูกค้า A"
    }
  }
}
```

> OA ตัวไหนใส่ key ก็ได้ Shopping tools ของตัวนั้น OA ตัวไหนไม่ใส่ ก็ใช้ได้แค่เครื่องมือข้อความ — ไม่มี error กวนใจ
> ลำดับการอ่านกุญแจ: `myshop_api_key` ของ OA นั้นก่อน → ถ้าไม่มี ใช้ env `LINE_MYSHOP_API_KEY`

### ขั้นที่ 3 — รีสตาร์ท host แล้วตรวจสอบ

1. ปิด AI host **ทั้งแอป** (Cmd+Q บน Mac) แล้วเปิดใหม่ — สำคัญมาก ไม่งั้นกุญแจไม่ถูกโหลด
2. ลองพิมพ์: **"ดูสินค้าทั้งหมดในร้าน"**
3. ถ้าได้รายการสินค้ากลับมา = สำเร็จ! เครื่องมือ Shopping 14 ตัวพร้อมใช้แล้ว (รวมเป็น 48 ตัว)

> 🧪 **อยากทดสอบ build ในเครื่องก่อน publish?** ดู [`cowork-local-test-th.md`](cowork-local-test-th.md) — ชี้ host ไปรัน `dist/index.js` ในเครื่องแทน npm

## 5. คู่มือทีละเครื่องมือ

แต่ละตัวมี: **ทำอะไร** · **พูดแบบนี้** (ตัวอย่างสั่ง AI) · **ข้อควรระวัง**

### 🛍️ กลุ่มสินค้า

#### `line_list_products` — ดูรายการสินค้า
ดูสินค้าทั้งหมดในร้าน แบ่งหน้าได้ (หน้าละ 1–100 ชิ้น ค่าเริ่มต้น 25) หรือกรองตามรหัสสินค้า/SKU

- 🗣️ "ดูสินค้าทั้งหมด" · "ขอสินค้าหน้า 2 หน้าละ 50" · "สินค้ารหัส Sample-01 มีอะไรบ้าง"
- ⚠️ ค้นด้วย "ชื่อ" ตรงๆ ไม่ได้ — ต้องกรองด้วยรหัสสินค้า (id) หรือ SKU เท่านั้น
- เครื่องมือนี้ **อ่านอย่างเดียว** ปลอดภัย ไม่กระทบร้าน

#### `line_create_product` — เพิ่มสินค้าใหม่
สร้างสินค้าได้ทั้งแบบตัวเดียว (ราคาเดียว) และแบบมีหลายตัวเลือก (variant เช่น S/M/L)

- 🗣️ "เพิ่มเสื้อยืด 299 บาท สต็อก 50" · "เพิ่มเสื้อโปโล 3 ไซส์ S=290 M=290 L=320"
- ⚠️ **สินค้าใหม่จะถูกซ่อนไว้ก่อน (ยังไม่ขาย)** ต้องสั่ง "เปิดขาย" ด้วย `line_set_product_visibility` ลูกค้าถึงจะเห็น
- ⚠️ ใส่รูปได้ แต่ต้องเป็น **ลิงก์ HTTPS ตรง** (MyShop ไม่มีปุ่มอัปโหลด) ดูหัวข้อความปลอดภัย

#### `line_update_product` — แก้ข้อมูลสินค้า
แก้ชื่อ รายละเอียด ยี่ห้อ หมวดหมู่ รูป — **แก้เฉพาะช่องที่บอก** ช่องอื่นคงเดิม

- 🗣️ "เปลี่ยนชื่อสินค้า 1008131408 เป็น 'กาแฟพรีเมียม'" · "อัปเดตรายละเอียดสินค้าตัวนี้"
- ⚠️ ตัวนี้ **ไม่แก้ราคาและสต็อก** — ราคาใช้ `line_update_product_price`, สต็อกใช้ `line_manage_inventory`

#### `line_update_product_price` — แก้ราคา + ส่วนลด
ตั้งราคาใหม่ และใส่ "ส่วนลดทันที" (instant discount) ได้ เช่น ตั้ง 350 ลด 51 → ลูกค้าจ่าย 299

- 🗣️ "ตั้งราคาสินค้านี้ 350" · "ลดสินค้านี้เหลือ 299 (จาก 350)"
- ⚠️ **แก้ราคาไม่ได้ถ้ากำลังมีโปรโมชันรันอยู่** — ต้องปิดโปรก่อน LINE ถึงจะให้แก้

#### `line_set_product_visibility` — เปิด/ปิดการขาย
เปิดขาย (`onsale`) หรือซ่อน (`hide`) สินค้า โดย**ไม่ลบ** ข้อมูลยังอยู่ครบ

- 🗣️ "เปิดขายสินค้า 1008131408" · "ซ่อนสินค้าตัวนี้ไว้ก่อน (ของหมด)"
- 💡 ใช้คู่กับ `create_product` เสมอ: สร้างเสร็จ → เปิดขาย / ของหมดก็ "ซ่อน" แทนการลบ

#### `line_manage_product_variant` — จัดการตัวเลือก (variant)
จัดการไซส์/สี ฯลฯ มี 3 โหมด: **เพิ่ม** variant ใหม่, **แก้** variant เดิม, **ลบ** ตัวเลือกที่ไม่มีแล้ว

- 🗣️ "เพิ่มไซส์ XL ราคา 390 ให้สินค้านี้" · "แก้ราคา variant นี้เป็น 350" · "ลบไซส์ XL ออก (ไม่มีแล้ว)"
- ⚠️ การลบตัวเลือกเอากลับไม่ได้ · variant คือ "ชุดราคา/สต็อก/รูป" ของแต่ละตัวเลือก สินค้า 1 ชิ้นมีได้หลาย variant

#### `line_delete_product` — ลบสินค้าถาวร
ลบสินค้าออกจากร้านอย่างถาวร

- 🗣️ "ลบสินค้า 1008131408 ยืนยัน"
- ⚠️ **ลบแล้วเอากลับไม่ได้** — ต้องยืนยัน (`confirm`) เสมอ ถ้าแค่อยากเอาออกจากการขายชั่วคราว ให้ใช้ "ซ่อน" (`set_product_visibility` → hide) จะปลอดภัยกว่า

### 📦 กลุ่มสต็อก

#### `line_manage_inventory` — จัดการสต็อก
ปรับสต็อกของ **variant** (ไม่ใช่ตัวสินค้า) มี 3 โหมด: **ตั้งค่า** (set = เขียนทับเป็นจำนวนนี้), **เพิ่ม** (increase), **ลด** (decrease) ใส่ได้ 1–100,000

- 🗣️ "ตั้งสต็อก variant นี้เป็น 100" · "เติมสต็อกอีก 50" · "ตัดสต็อกออก 20"
- ⚠️ ต้องใช้ **รหัส variant** ไม่ใช่รหัสสินค้า · `availableNumber` (พร้อมขาย) = สต็อกจริง − ที่ลูกค้าจองไว้ (reserved)
- 💡 ปลอดภัยกว่าถ้าใช้ "เพิ่ม/ลด" แทน "ตั้งค่า" เวลามีออเดอร์วิ่งพร้อมกัน

### 🧾 กลุ่มออเดอร์

#### `line_list_orders` — ดู/ค้นออเดอร์
ดูออเดอร์ กรองได้ทั้งสถานะออเดอร์ สถานะจ่ายเงิน วิธีจ่าย (โอน/COD/Rabbit LINE Pay) ช่วงเวลา และค้นชื่อลูกค้า/เลขออเดอร์

- 🗣️ "ออเดอร์วันนี้ที่จ่ายแล้ว" · "ค้นออเดอร์ของคุณสมชาย" · "ออเดอร์ COD ที่ยังไม่จ่าย"
- ⚠️ **ไม่มี webhook แจ้งออเดอร์ใหม่** (ตั้งใจ เพื่อไม่ต้องมีเซิร์ฟเวอร์) อยากรู้ออเดอร์ใหม่ ให้ตั้ง [Scheduled Task](#) เรียกตัวนี้เป็นรอบ เช่น ทุก 5 นาที กรอง `payment_status: PAID` + ช่วงเวลาตั้งแต่รอบที่แล้ว

#### `line_get_order` — รายละเอียดออเดอร์
ดูข้อมูลเต็มของออเดอร์เดียว — ลูกค้า ที่อยู่ รายการสินค้า ยอดเงิน สถานะทั้งหมด

- 🗣️ "ดูรายละเอียดออเดอร์ 100023"
- 💡 ต้องรู้เลขออเดอร์ก่อน (ได้จาก `list_orders`)

#### `line_fulfill_order` — จัดการส่งของ
เครื่องมือเดียว 4 โหมด: **ship** (ทำเครื่องหมายส่งแล้ว + ใส่เลขพัสดุ), **update_tracking** (แก้เลขพัสดุ), **paid** (ยืนยันรับเงิน COD), **parcel_label** (ออกใบปะหน้าพัสดุ)

- 🗣️ "ส่งของออเดอร์ 100023 เลขพัสดุ TH123" · "ออกใบปะหน้าออเดอร์นี้" · "ออเดอร์ COD นี้รับเงินแล้ว"
- ⚠️ โหมด **ship จะส่งข้อความ LINE แจ้งลูกค้าโดยอัตโนมัติ** (ลูกค้ารู้ทันทีว่าของส่งแล้ว) · ออเดอร์ COD ต้อง ship ก่อน แล้วค่อย paid ออเดอร์ถึงจะปิดเป็น COMPLETED · เลขพัสดุยาวได้ไม่เกิน 50 ตัวอักษร

#### `line_cancel_order` — ยกเลิกออเดอร์
ยกเลิกออเดอร์ (ถ้าจ่ายแล้วระบบจะคืนเงิน และคืนสต็อกที่จองไว้)

- 🗣️ "ยกเลิกออเดอร์ 100023 ยืนยัน"
- ⚠️ **ยกเลิกแล้วเอากลับไม่ได้** — ต้องยืนยัน (`confirm`) เสมอ

### 💰 กลุ่มเงิน

#### `line_get_settlement` — ดูเงินที่ได้จริง
ดูยอดสุทธิของออเดอร์ — ราคาสินค้า ค่าส่ง ลบค่าธรรมเนียม LINE = **เงินที่ร้านได้จริง**

- 🗣️ "ออเดอร์ 100023 ได้เงินจริงเท่าไหร่" · "ดูค่าธรรมเนียมออเดอร์นี้"
- 💡 LINE หักค่าธรรมเนียม (commission) ตามแพ็กเกจร้าน — ดูตัวเลขจริงต่อออเดอร์ได้จากเครื่องมือนี้ ไม่ต้องเดา

#### `line_create_checkout_link` — สร้างลิงก์จ่ายเงิน ⭐
สร้างลิงก์จ่ายเงินของสินค้าชุดหนึ่ง (1–15 รายการ) ส่งให้ลูกค้าในแชท → ลูกค้ากดจ่ายจบ → ออเดอร์เกิดอัตโนมัติ

- 🗣️ "สร้างลิงก์จ่ายเงิน variant V9 จำนวน 2 ชิ้น" · "ทำลิงก์จ่ายเงินสินค้า A 1 ชิ้น กับ B 3 ชิ้น"
- ⚠️ สินค้าที่มีหลายตัวเลือก **ต้องระบุ variant_id ไม่ใช่ product_id** (ไม่งั้นระบบไม่รู้ว่าไซส์ไหน) · นี่คือพระเอกของการ "ปิดการขายในแชท"

## 6. Workflow จริง

### A) ลงสินค้าใหม่ให้ขายได้

```
1. "เพิ่มเสื้อยืด Cofftail 320 บาท สต็อก 50"   → line_create_product (ได้รหัสสินค้ากลับมา)
2. "ใส่รูปสินค้าตัวนี้: https://.../shirt.jpg"   → line_update_product
3. "เปิดขายสินค้าตัวนี้"                          → line_set_product_visibility (onsale)
4. "ดูสินค้าทั้งหมด เช็กว่าขึ้นแล้ว"             → line_list_products
```
> จำไว้: ข้ามขั้น 3 ไม่ได้ — สินค้าใหม่ถูกซ่อนไว้ก่อนเสมอ

### B) ปิดการขายในแชท (ลูกค้าทักมาซื้อ)

```
1. "ดูสินค้า เอารหัส variant ของไซส์ M"          → line_list_products
2. "สร้างลิงก์จ่ายเงิน variant นั้น 2 ชิ้น"        → line_create_checkout_link
3. ก็อปลิงก์ที่ได้ → วางส่งลูกค้าในแชท LINE
4. ลูกค้ากดจ่าย → ออเดอร์เกิดอัตโนมัติ
```

### C) จัดการออเดอร์ที่เข้ามา

```
1. "ออเดอร์วันนี้ที่จ่ายแล้ว"                     → line_list_orders (payment_status: PAID)
2. "ดูรายละเอียดออเดอร์ 100023"                  → line_get_order
3. "ออกใบปะหน้าออเดอร์นี้"                        → line_fulfill_order (parcel_label)
4. "ส่งของแล้ว เลขพัสดุ TH123456"                 → line_fulfill_order (ship) → ลูกค้าได้ LINE แจ้งอัตโนมัติ
5. "ออเดอร์นี้ได้เงินสุทธิเท่าไหร่"               → line_get_settlement
```

### D) เช็กออเดอร์ใหม่อัตโนมัติ (ไม่มี webhook)

ตั้ง Scheduled Task ให้เรียก `line_list_orders` เป็นรอบ เช่นทุก 5 นาที กรอง `payment_status: PAID` ตั้งแต่เวลารอบที่แล้ว → มีออเดอร์ใหม่ค่อยแจ้งเตือน

## 7. กฎความปลอดภัยที่ต้องรู้

| เรื่อง | สิ่งที่ต้องระวัง |
|---|---|
| 🔒 **กุญแจเป็นความลับ** | `LINE_MYSHOP_API_KEY` อยู่ใน env/ไฟล์ config เท่านั้น ห้ามวางในโค้ด แชท หรือ commit ขึ้น git |
| 👁️ **สินค้าใหม่ถูกซ่อน** | สร้างเสร็จต้อง "เปิดขาย" (`set_product_visibility` → onsale) เสมอ ไม่งั้นลูกค้าไม่เห็น |
| 🖼️ **รูปต้อง host เอง** | MyShop ไม่มีปุ่มอัปโหลด ต้องใช้ลิงก์ HTTPS ตรง (Cloudflare R2 / S3 / Cloudinary / raw.githubusercontent) **เลี่ยง** ลิงก์แชร์ Google Drive/Dropbox (คืนหน้า preview ไม่ใช่ไฟล์รูป LINE อ่านไม่ได้) |
| ⚠️ **ลบ/ยกเลิกต้องยืนยัน** | `delete_product` และ `cancel_order` เอากลับไม่ได้ ต้อง `confirm` เสมอ — อยากเอาสินค้าออกชั่วคราวให้ "ซ่อน" แทนลบ |
| 💸 **แก้ราคาตอนมีโปรไม่ได้** | LINE ล็อกราคาขณะโปรโมชันรันอยู่ ต้องปิดโปรก่อน |
| 📨 **ส่งของ = ลูกค้าได้ LINE** | โหมด ship ของ `fulfill_order` ส่งข้อความแจ้งลูกค้าอัตโนมัติ ตรวจเลขพัสดุให้ถูกก่อนกด |
| 🚦 **อย่ายิงถี่เกิน** | MyShop จำกัด 50 ครั้ง/วินาที และ 1,000 ครั้ง/นาที เกินแล้วจะโดน HTTP 429 |
| 🆔 **variant ≠ product** | จัดการสต็อกและ checkout link ของสินค้าหลายตัวเลือก ต้องใช้ "รหัส variant" ไม่ใช่ "รหัสสินค้า" |

## 8. แก้ปัญหาที่เจอบ่อย

**❓ เครื่องมือ Shopping ไม่โผล่ (เห็นแค่ 34 ตัว)**
- ยังไม่ได้ใส่ `LINE_MYSHOP_API_KEY` หรือใส่แล้วแต่ยังไม่ได้รีสตาร์ท host ทั้งแอป
- ใช้ `npx` ตัวเก่าจาก npm ที่ยังไม่มี Shopping (ตอนเทส build ใหม่ ต้องชี้ไป `dist/index.js` ในเครื่อง ดู [`cowork-local-test-th.md`](cowork-local-test-th.md))
- ร้านยังไม่ได้เปิด LINE Shopping

**❓ ขึ้น "ไม่มีสิทธิ์ / API Key ไม่ถูกต้อง" (401)**
- กุญแจผิด หมดอายุ หรือไม่ได้ออกจาก role Admin → ออกใหม่ที่ oaplus.line.biz → Settings → API keys

**❓ ขึ้น "คำขอเกินขีดจำกัด" (429)**
- ยิงถี่เกิน 50 ครั้ง/วินาที — เว้นจังหวะแล้วลองใหม่

**❓ รูปสินค้าไม่ขึ้น**
- ลิงก์ไม่ใช่ HTTPS ตรง หรือเป็นลิงก์แชร์ Google Drive/Dropbox → เปลี่ยนไปใช้ที่ฝากรูปที่คืนไฟล์ตรง

**❓ ลูกค้ายังไม่เห็นสินค้าที่เพิ่ง add**
- ลืม "เปิดขาย" — สั่ง "เปิดขายสินค้าตัวนี้" (`set_product_visibility` → onsale)

**❓ แก้ราคาไม่ได้**
- มีโปรโมชันรันอยู่ → ปิดโปรก่อนค่อยแก้ราคา

## 9. อภิธานศัพท์

| คำ | ความหมาย |
|---|---|
| **MyShop / LINE Shopping** | ระบบร้านค้าในตัวของ LINE OA |
| **MyShop API Key** | กุญแจสำหรับสั่งงานฝั่งร้านค้า (คนละตัวกับ Channel Access Token) |
| **Product (สินค้า)** | ตัวสินค้า 1 รายการ อาจมีหลาย variant |
| **Variant (ตัวเลือก)** | ชุดราคา/สต็อก/รูปของแต่ละไซส์/สี เช่น เสื้อตัวเดียวมี variant S, M, L |
| **SKU** | รหัสสินค้าภายในร้านที่คุณตั้งเอง (เช่น Sample-01) |
| **Reserved (จองไว้)** | สต็อกที่ลูกค้าสั่งแล้วแต่ยังไม่จ่าย — ถูกกันไว้ ไม่นับเป็นพร้อมขาย |
| **Settlement** | สรุปเงินสุทธิที่ร้านได้จริงหลังหักค่าธรรมเนียม |
| **COD** | เก็บเงินปลายทาง (Cash on Delivery) |
| **RLP** | Rabbit LINE Pay |
| **Checkout link** | ลิงก์จ่ายเงินที่ส่งให้ลูกค้าปิดการขายในแชท |
| **Polling** | การเรียกเช็กออเดอร์เป็นรอบ (แทนการมี webhook คอยแจ้ง) |
