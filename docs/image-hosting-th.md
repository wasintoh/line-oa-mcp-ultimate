# ส่งรูปเข้า LINE โดยไม่ต้องมีโฮสต์ — Image Hosting Layer (v2.2)

> สำหรับเจ้าของร้าน / นักการตลาด ที่อยากส่งรูปหรือ Rich Message เข้า LINE OA
> **โดยไม่ต้องรู้จักคำว่า hosting เลยแม้แต่คำเดียว** · English: [image-hosting.md](image-hosting.md)

---

## ปัญหาเดิมคืออะไร

LINE ไม่รับ "ไฟล์รูป" ตรงๆ — เวลาส่งข้อความรูปหรือ Rich Message เราต้องส่ง **ลิงก์ (URL)** ให้
แล้ว LINE จะเดินมาดึงรูปจากลิงก์นั้นเอง แถม Rich Message ยังต้องมีรูป **5 ขนาด** ให้ครบอีก

แปลว่าเมื่อก่อน ใครอยากส่งรูปต้อง: หาที่ฝากรูปเอง → ย่อรูปเป็น 5 ขนาดเอง → ตั้งชื่อไฟล์ให้ถูกแบบเอง
ซึ่งตัดคนใช้ทั่วไปออกไปเกือบหมด

## v2.2 แก้ยังไง

เพิ่ม tool ใหม่ `line_prepare_image` — ทำให้ทั้งหมดข้างบน**หายไปในคำสั่งเดียว**:

```
พิมพ์กับ AI: "ส่งรูปนี้เป็น Rich Message เข้าไลน์ให้หน่อย" (แนบรูป)
```

เบื้องหลัง ระบบจะ:

1. **ย่อรูป** เป็น 5 ขนาดที่ LINE ต้องการ (1040/700/460/300/240) ให้อัตโนมัติ
2. **เปิดที่ฝากรูปชั่วคราว** ให้เอง (ดูหัวข้อ "3 ช่องทาง" ด้านล่าง)
3. **ตรวจจริง** ว่า LINE ดึงรูปได้ครบทุกขนาด — ถ้าขนาดไหนพัง จะบอกตรงๆ ไม่หลอกว่าสำเร็จ
4. คืน `prepared_key` (คิดเสมือน "ใบรับฝากรูป") — เอาไปใช้กับ `line_design_imagemap` และ
   `line_send_message` ได้เลย ไม่ต้องพิมพ์ URL ยาวๆ อีก

## 3 ช่องทางที่ระบบเลือกให้เอง (ไม่ต้องตั้งค่าอะไร)

| ช่องทาง | เหมาะกับใคร | ทำงานยังไง |
|---|---|---|
| **self** | คนที่รัน MCP บนเซิร์ฟเวอร์อยู่แล้ว (HTTP mode) | เซิร์ฟเวอร์ของคุณเสิร์ฟรูปเอง — ตั้ง env `MCP_PUBLIC_URL` ครั้งเดียวจบ |
| **local-tunnel** (ค่าเริ่มต้น) | คนทั่วไปที่ติดตั้งผ่าน `npx` | เปิด "สะพานชั่วคราว" (cloudflared — ฟรี ไม่ต้องสมัคร) ให้ LINE มองเห็นเครื่องคุณชั่วขณะที่ส่ง แล้วปิดเอง |
| **handoff** | เครือข่ายองค์กรที่บล็อกทุกอย่าง | ได้ไฟล์ zip รูปครบ 5 ขนาด + คู่มือทำเอง 3 ทางเลือก จบใน 1 นาที — **ไม่มีใครเจอทางตัน** |

## เรื่องสำคัญที่ต้องรู้ (อ่านข้อนี้ข้อเดียวก็พอ)

**LINE จะมาดึงรูปตอนที่ลูกค้า "เปิดอ่านข้อความครั้งแรก" — ไม่ใช่ตอนส่ง**
(พิสูจน์ด้วยการทดลองจริง 31 ก.ค. 2026: ข้อความที่ไม่มีใครเปิดอ่านเลย พอปิดที่ฝากรูปแล้วรูปหาย
แต่ข้อความที่ถูกเปิดอ่านแล้ว รูปอยู่ถาวรแม้ปิดเครื่องและ restart มือถือ)

กติกาที่ตามมา:

- ⏰ **ส่งแล้วเปิดเครื่อง + เปิดโปรแกรมทิ้งไว้ จนกว่าลูกค้าส่วนใหญ่จะเปิดอ่าน** — ระบบเปิดที่ฝากรูปค้างไว้ให้ 24 ชม. อัตโนมัติ (ปรับได้)
- ✅ ลูกค้าที่เปิดอ่านแล้ว = LINE เก็บรูปให้ถาวร ปิดเครื่องได้เลย ไม่กระทบคนที่เปิดอ่านไปแล้ว
- ⚠️ ลูกค้าที่ยังไม่เปิดอ่านตอนที่ฝากรูปปิดไปแล้ว จะเห็น "ไม่สามารถโหลดรูปได้"
- 🔁 ถ้าปิดโปรแกรมแล้วเปิดใหม่ `prepared_key` เดิมจะใช้ไม่ได้ → เรียก `line_prepare_image` ใหม่ (ไม่กี่วินาที)
- 📌 แคมเปญใหญ่/ระยะยาวที่ปิดเครื่องไม่ได้ → ใช้โฮสต์ถาวร (R2 / GitHub Pages ฯลฯ) แล้วส่ง `base_url` แบบเดิม หรือ deploy แบบ HTTP + `MCP_PUBLIC_URL` บนเซิร์ฟเวอร์ที่เปิดตลอด (v2.3 จะทำโฮสต์ถาวรให้อัตโนมัติ)
- 🖼️ แนบรูปให้ tool ด้วย `file_path` หรือ `source_url` เป็นหลัก — `base64` เป็นทางเลือกสุดท้าย (ข้อมูลยาวๆ ที่เดินทางผ่าน AI อาจเพี้ยนแบบเงียบๆ แล้วได้ภาพว่างเปล่า)

## การตั้งค่า (ทั้งหมดเป็น "ทางเลือก" — ไม่ตั้งอะไรเลยก็ใช้ได้)

| Env | ใช้ทำอะไร |
|---|---|
| `MCP_PUBLIC_URL` | (HTTP mode) บอก URL สาธารณะของเซิร์ฟเวอร์ เช่น `https://line-mcp.myshop.com` → เปิดช่องทาง self |
| `LINE_MCP_TUNNEL=off` | ปิดสะพานชั่วคราว (สำหรับองค์กรที่นโยบายห้าม) → ระบบจะข้ามไป handoff |
| `LINE_MCP_CLOUDFLARED_PATH` | ชี้ไปที่ cloudflared ที่ติดตั้งเองแล้ว (ระบบจะไม่ดาวน์โหลดใหม่) |

หมายเหตุความปลอดภัย: cloudflared ที่ดาวน์โหลดอัตโนมัติถูก **ตรวจลายนิ้วมือไฟล์ (SHA-256)**
กับเวอร์ชันที่ล็อกไว้ก่อนรันเสมอ · รูปถูกเสิร์ฟจากหน่วยความจำเท่านั้น (ไม่มีทางอ่านไฟล์อื่นในเครื่อง)
· ลิงก์รูปเป็นรหัสสุ่มยาวที่เดาไม่ได้

## ถ้าพัง ให้ทำอะไร

| อาการ | ทางแก้ |
|---|---|
| ระบบบอก "เปิดโฮสต์อัตโนมัติไม่ได้" | ได้ zip + คู่มือมาแล้ว — ทำตาม 3 ทางเลือกในนั้น (ง่ายสุด: LINE OA Manager) |
| "รูปขนาด X ยังเปิดไม่ติด" | เรียก `line_prepare_image` ใหม่อีกครั้ง — ระบบจะเปิดช่องทางใหม่ให้ |
| "ไม่พบ prepared_key" | โปรแกรมถูกปิด-เปิดใหม่ — เตรียมรูปใหม่ด้วย `line_prepare_image` |
| อยากรู้ว่าช่องทางไหนใช้ได้บ้าง | เรียก `line_image_host_status` (ตัวนี้อ่านอย่างเดียว ปลอดภัย) |
| ส่งรูปจากคอมพ์คนละเครื่องกับ MCP (เช่น Cowork cloud) | ให้ AI ส่งรูปแบบ base64 มาที่ tool ได้ (จำกัด ~3MB) หรือใช้ `source_url` |

## สำหรับสาย automation (n8n / VPS / agency)

รัน MCP แบบ HTTP transport (`MCP_TRANSPORT=http`) + ตั้ง `MCP_PUBLIC_URL` ให้ตรงกับ
โดเมนหน้าบ้าน — เท่านี้ workflow ใน n8n (ผ่าน MCP Client node) ก็สั่ง
`line_prepare_image` → `line_send_message` ได้ครบวงจร โดยรูปถูกเสิร์ฟจากเซิร์ฟเวอร์เดียวกัน
ไม่ต้องมีสะพานชั่วคราวเลย · รายละเอียด HTTP mode: [http-transport.md](http-transport.md)

> ℹ️ TryCloudflare (สะพานชั่วคราว) เป็นบริการฟรีสำหรับงานพัฒนา ไม่มี SLA —
> เหมาะกับ "ช่วงรอลูกค้าเปิดอ่าน" (ชั่วโมง-วัน) ไม่ใช่ที่เก็บรูปถาวร — พอลูกค้าเปิดอ่านแล้ว
> LINE เก็บรูปให้ถาวรเอง ภาระของสะพานจึงจบตรงนั้นพอดี
