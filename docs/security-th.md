# ความปลอดภัย — คู่มือสำหรับเจ้าของร้าน (Threat Model ฉบับอ่านง่าย)

> เอกสารนโยบายรับแจ้งช่องโหว่ (ภาษาอังกฤษ) อยู่ที่ [`SECURITY.md`](../SECURITY.md)

MCP server ตัวนี้ทำงานด้วย **channel access token** ของ LINE OA ร้านคุณ
พูดตรง ๆ คือ: **ใครถือ token = คนนั้นคือร้านคุณ** เอกสารนี้อธิบายว่า
token ทำอะไรได้ อะไรคือความเสี่ยงจริง และตั้งค่าอย่างไรให้ปลอดภัย

## 1. Token ของร้านทำอะไรได้บ้าง

ถ้า token หลุดไปถึงมือคนอื่น เขาสามารถ:

- **ส่งข้อความหาลูกค้าทุกคนของร้าน** (broadcast) — รวมถึงข้อความหลอกลวง/ลิงก์ปลอมในนามร้านคุณ
- ดึงรายชื่อผู้ติดตามและโปรไฟล์ลูกค้า
- เปลี่ยน rich menu (เมนูหลักที่ลูกค้าเห็น) เป็นอะไรก็ได้
- สร้าง/แก้คูปอง, เปลี่ยน webhook endpoint ให้ข้อความลูกค้าวิ่งไปหาเซิร์ฟเวอร์ของเขา
- ถ้าตั้ง MyShop API key ไว้ด้วย: แก้ราคาสินค้า สต๊อก ออเดอร์ และดูยอดเงินรอโอน

**สรุป: ปฏิบัติกับ token เหมือนกุญแจหน้าร้าน + สมุดบัญชีลูกค้าในชิ้นเดียว**

## 2. แยก token ต่อ OA (อย่าใช้ key เดียวคุมทุกร้าน)

- ใช้ **token แยกของแต่ละ OA** ใน `~/.line-mcp/config.json` — ถ้า token ของร้านหนึ่งหลุด อีกร้านไม่โดนด้วย
- เอเจนซี่ที่ดูแลหลายร้าน: อย่าแชร์ config file เดียวกันข้ามเครื่อง/ข้ามทีมโดยไม่จำเป็น
- สงสัยว่า token หลุด → เข้า LINE Developers Console แล้ว **ออก token ใหม่ทันที** (token เก่าจะใช้ไม่ได้) จากนั้นใช้ `line_check_token` ตรวจว่า token ใหม่ใช้งานได้

## 3. สิทธิ์ไฟล์ config (สำคัญมากบนเครื่องที่ใช้ร่วมกัน)

ไฟล์ `~/.line-mcp/config.json` เก็บ token จริงแบบ plain text — อย่าให้ user อื่นบนเครื่องอ่านได้:

```bash
chmod 600 ~/.line-mcp/config.json
```

ตั้งแต่ v2.1 ถ้าไฟล์เปิดสิทธิ์ให้คนอื่นอ่านได้ server จะเตือนตอนเริ่มทำงานพร้อมคำสั่ง chmod ให้ copy ได้เลย

## 4. โหมด HTTP ต้องตั้ง MCP_HTTP_TOKEN

โหมดปกติ (stdio) ไม่เปิด port อะไรเลย — ปลอดภัยสุด ใช้อันนี้ถ้าไม่มีเหตุจำเป็น

ถ้าต้องใช้โหมด HTTP:

- ค่าเริ่มต้น bind ที่ `127.0.0.1` (เครื่องตัวเองเท่านั้น) — ดีอยู่แล้ว
- ตั้ง token ประจำ endpoint:

```bash
MCP_HTTP_TOKEN="สุ่มยาวๆ-อย่างน้อย-32-ตัวอักษร" MCP_TRANSPORT=http npx -y line-oa-mcp-ultimate
```

- ทุก request ต้องแนบ `Authorization: Bearer <token>` ไม่งั้นโดนปฏิเสธ (401) ทันที
- **v2.1 จะไม่ยอมเปิด server บน host อื่นที่ไม่ใช่ loopback (เช่น `0.0.0.0`) ถ้าไม่ตั้ง `MCP_HTTP_TOKEN`** — เพราะเท่ากับเปิดให้ทุกคนในเครือข่าย broadcast ในนามร้านคุณ
- ต้องการเปิดออก internet จริง ๆ → วาง reverse proxy ที่ทำ TLS (https) ข้างหน้าเสมอ
- ดูขั้นตอนละเอียดที่ [`docs/http-transport.md`](http-transport.md)

## 5. ระบบกันพลาด/จำกัดความเสียหายที่เปิดให้อัตโนมัติ

ต่อให้ agent (หรือคนที่สั่ง agent) พลาด ระบบเหล่านี้ช่วยจำกัดวงความเสียหาย:

- **Quota Guardian** — ถ้าการส่งจะกินเกิน 95% ของ quota ที่เหลือ ต้องยืนยัน `confirm=true` ก่อน ป้องกันการ broadcast เผาโควต้า (และเงิน) ในคำสั่งเดียว
- **Quiet hours (22:00–08:00 น.)** — ส่งกลางดึกต้อง `force=true` ป้องกันข้อความตีสามที่ทำลูกค้า block ร้าน
- **Broadcast ถึงทุกคนต้อง `confirm=true` เสมอ**
- **Secret redaction (v2.1)** — ถ้า error จาก LINE ดันสะท้อน token กลับมา ข้อความที่แสดงจะถูกแทนที่เป็น `***REDACTED***` ไม่หลุดเข้า log หรือหน้าจอแชท
- **SSRF guard (v2.1)** — URL รูปที่ส่งให้ server ไปดาวน์โหลด (เช่น รูป rich menu) ต้องเป็น https สาธารณะเท่านั้น ชี้เข้าเครือข่ายภายใน/cloud metadata จะถูกปฏิเสธ

## 6. ข้อจำกัดที่เรารู้ตัว (บอกไว้ตรงนี้ ดีกว่าให้ไปเจอเอง)

ไม่มีระบบไหนปิดได้ 100% เราเลยเขียนสิ่งที่ยัง "ปิดไม่สนิท" ไว้ให้ครบ จะได้ตัดสินใจบนข้อมูลจริง
รายละเอียดเชิงเทคนิคเต็ม ๆ อยู่ที่หัวข้อ *Known limitations* ใน [`SECURITY.md`](../SECURITY.md)

**1) SSRF guard ยังมีช่องแคบ ๆ เรื่อง DNS**

ตอนจะโหลดรูปจาก URL ที่คุณให้มา server เช็คก่อนว่าชื่อโดเมนนั้นไม่ได้ชี้เข้าเครือข่ายภายใน
แต่ตอน "โหลดจริง" มันถามที่อยู่ของโดเมนนั้นใหม่อีกรอบ — ถ้าคนร้ายคุมโดเมนนั้นได้
และสลับคำตอบระหว่างสองจังหวะนี้ ก็มีโอกาสเล็ดลอดผ่านได้

- **กระทบแค่ไหน:** เฉพาะ 2 เครื่องมือที่ต้องโหลดรูปจาก URL คือ `line_upload_rich_menu_image` กับ `line_build_rich_menu`
- **ต้องเกิดพร้อมกัน 2 อย่างถึงจะโดน:** คนร้ายต้องเป็นคนกำหนด URL รูปที่ AI จะโหลด **และ** ต้องคุมระบบชื่อโดเมนนั้นเองด้วย
- **ตอนนี้ทำอะไรได้:** ใช้รูปจากแหล่งที่คุณคุมเอง — อย่าเอา URL แปลก ๆ ที่ลูกค้าส่งมาในแชทให้ AI โหลดตรง ๆ
- **แผนแก้จริง:** ต้องเขียนตัวเชื่อมต่อเองให้ "ล็อก" ที่อยู่ที่ตรวจผ่านแล้วไว้จนจบการโหลด — เลื่อนไปทำใน minor release เพราะมันแตะเส้นทางโหลดของทุกเครื่องมือ ต้องมีชุดทดสอบของตัวเอง

**2) พิมพ์ชื่อ option ชั้นบนสุดผิด ระบบจะเงียบ ไม่ฟ้อง**

ถ้า AI ส่งชื่อ option ชั้นนอกสุดผิด (เช่นพิมพ์ `dryrun` แทน `dry_run`) ระบบจะ **ข้ามทิ้งเฉย ๆ**
แทนที่จะเตือน แล้วคำสั่งก็ทำงานด้วยค่าเริ่มต้นแทน

- **อันตรายจริงคือ:** นึกว่าสั่ง "ซ้อม" แต่กลายเป็น "ส่งจริง" 😅
- **วิธีกัน:** เวลาทดสอบ ให้ดูที่ **ผลลัพธ์** ว่าขึ้นว่าเป็นโหมดซ้อมจริงไหม อย่าเชื่อแค่ว่าพิมพ์ไปแล้วต้องติด
- ข้อมูลชั้นในลึกกว่านั้น (ตัวข้อความ, ปลายทางที่ส่ง, พื้นที่กดใน rich menu) ยังเข้มงวดตามปกติ — พิมพ์ผิดฟ้องแน่นอน

**3) โควต้าเหลือ 0 ระบบจะขอให้ยืนยันทุกครั้ง**

อันนี้ตั้งใจ ไม่ใช่บั๊กค่ะ — พอโควต้าข้อความเดือนนั้นหมดเกลี้ยง ระบบเลือกจะ "ถามก่อนเสมอ"
ดีกว่าเดาแล้วพลาด เขียนไว้ตรงนี้เพื่อจะได้ไม่มีใครไปแจ้งว่าเป็นบั๊ก

## 7. เช็กลิสต์ 1 นาที

- [ ] `chmod 600 ~/.line-mcp/config.json`
- [ ] token แยกต่อ OA, ไม่ hard-code ใส่สคริปต์/แชร์ผ่านแชท
- [ ] ใช้ stdio ถ้าไม่จำเป็นต้องใช้ HTTP
- [ ] ถ้าใช้ HTTP: ตั้ง `MCP_HTTP_TOKEN` + อยู่หลัง reverse proxy เมื่อออกนอกเครื่อง
- [ ] รูปที่ให้ AI โหลด ใช้จากแหล่งที่คุณคุมเอง ไม่ใช่ URL จากแชทลูกค้า
- [ ] สงสัย token หลุด → ออก token ใหม่ใน LINE Developers Console ทันที
- [ ] เจอช่องโหว่ของตัว server → แจ้งแบบส่วนตัวผ่าน GitHub Security Advisories (ดู [`SECURITY.md`](../SECURITY.md))
